# Vyvræl 0.1.0

*A dragon-flavoured UCI chess engine in Rust, built with AI and playing for
the attack.*

The first release built by the release workflow, and the first with a
measurement of strength. It plays exactly as 0.1.0-alpha.2 did at full
strength. What is new is around it: the engine measured against an
opponent ladder, `UCI_Elo` calibrated on that ladder's scale, and the
tools that made both possible.

## Read this first

- **Which file to take:** `vyvrael-0.1.0-avx2.exe` (Windows) or
  `vyvrael-0.1.0-avx2` (Linux), the primary build, for any processor with
  AVX2 and BMI2 (Intel from Haswell, 2013; AMD from Excavator and Zen).
  Take the plain `vyvrael-0.1.0.exe` or `vyvrael-0.1.0` only on an older
  machine where the `avx2` file does not start. A `pext` build follows
  with milestone 7 (0.2.0).
- **Breaking for GUI settings:** `UCI_Elo` now runs from **1110 to 1630**
  (it was 400 to 1800), with the default **1360**, which plays exactly as
  the old default did. A GUI or script that sets a value outside the new
  range has it refused, and the old value stays.
- **Measured, provisionally.** On the project's own opponent ladder,
  0.1.0 scores about level with Rodent IV-2000 (49.5% in 100 games) and
  0.1.0-alpha.2 (48%), and below Stockfish 19-1800 (30%). Ordo puts it at
  -1721.4 with Stockfish 19 as 0, which is 1,779 on the `UCI_Elo` scale.
  **This is an ordering against other engines on a stretched scale, not a
  Lichess, CCRL or FIDE rating,** and its error against the anchor is
  about ±225. Details below and in
  [results-0.1.0.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/testing/results-0.1.0.md).
- **A casual-only Lichess bot** runs on the account `Vyvrael-Chess`, run
  by the maintainer. Rated games wait until after 0.2.0. See
  [LICHESS.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/LICHESS.md).
- **Built under the 0rwx X scale.** The code is written by AI coding agents
  and curated by the maintainer, who does not read every line. Trust rests
  on the tests, the documentation and a history of small commits. See
  <https://0rwx.com/> and the
  [README](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/README.md).

## What is measured, and what is not

- **The rating cited here is of this release's source.** It was measured
  before the release, on the maintainer's Windows workstation, with an
  `avx2` build (`-C target-cpu=x86-64-v3`) of the release's source built
  by hand with the local toolchain: the same Rust version (1.100.0) as the
  workflow, but its GNU target where the workflow builds for Windows with
  MSVC. It is the same source and build level as the released `avx2`
  file, not the workflow's binary itself. Its search is the same, which the bench node count shows
  (16,611,416 for both); only its speed may differ slightly.
- **How:** 1,000 games at 10 seconds plus 0.1 a move against ten rungs of
  Ladder Baseline 2, rated together with that ladder's 1,740 games by
  Ordo. Scores against each opponent and the full table are in
  [results-0.1.0.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/testing/results-0.1.0.md).
- **How precise:** the same search, measured once before as
  0.1.0-alpha.2 with different openings, came out at -1665.5 (1,835 on
  the scale). The 56 points between the two runs are the spread of such a
  measurement, not a change in the engine.
- **`UCI_Elo` is calibrated, provisionally.** Seven settings of the
  weakening were measured on the same ladder, and the option maps a rating
  through them: two plies of lookahead from 1110, three from 1350, with
  less misjudgement as the number rises. A setting of 1,200 means about as
  strong as an engine rated 1,200 on this ladder, not a 1,200 player.
  Ratings below 1110 cannot be played: the weakest setting already beats
  the two lowest rungs of the ladder in most games. See
  [UCI.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/UCI.md),
  "Limited strength", and
  [TESTING.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/TESTING.md),
  "Calibration of `UCI_Elo`".
- **Both are provisional:** they hold for this build. They are measured
  again after milestone 7 and after the planned speed work, which will
  change the engine's strength.
- **Not measured:** strength in a chess GUI against people, and anything
  about Lichess ratings.

## What is new

- **The release workflow** builds the binaries on GitHub: an `avx2` and a
  plain build for Windows and Linux, each smoke-tested and with a
  `.sha256` file. The Rust toolchain is pinned to 1.100.0, so local
  builds, CI and these binaries use the same compiler.
- **`UCI_Elo` calibrated** (see above).
- **A robustness test** feeds the UCI loop seeded streams of malformed and
  unexpected input (random bytes, broken FENs, oversized and cut-off
  lines, odd option values, commands during a search). It found no panic.
- **Testing tools** (for developers, not needed to play): the match
  scripts record more in their run notes (the commit, the games, the
  PGN's SHA-256) and can give a build its own UCI options, which is how
  the limited settings were measured; the installer also provides
  eleven new opponents for the next ladder, Ladder Baseline 3. See
  [TESTING.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/TESTING.md).

The full list is in the
[changelog](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/CHANGELOG.md).

## Known limitations

From the "Known issues" table in
[ROADMAP.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.1.0/docs/ROADMAP.md):

- **KI-9:** the main search has no move ordering yet, so it searches
  shallowly for the time it uses (milestone 7).
- **KI-10:** the first search depth cannot be interrupted, and in
  positions with very many captures it can overrun a short time budget.
- **KI-12:** a long game with no increment and a tiny clock can be lost
  on time (seen once in 204 games at one second a side). Games with an
  increment are not affected.
- **KI-8:** the evaluation is untuned; its strength is measured for this
  build only.
- **KI-2:** FEN parsing is strict and has no repair mode for sloppy input.
- **KI-11, KI-13:** two limitations of the developer tools (the
  lichess-bot installer and the rating script).

Also: `Hash` is accepted but has no effect yet, `Threads` can only be 1,
and there is no pondering, `searchmoves` or `go mate`.

## How it was checked

- **Tests:** 461 Rust tests (unit tests and the integration suites:
  perft, UCI over real pipes, malformed input, pinned search results and
  the pinned bench count, whole games) and 246 tests of the helper
  scripts, all passing, with `cargo fmt` and `cargo clippy -D warnings`
  clean, on the maintainer's Windows workstation. The release workflow
  runs the same gates again on the tagged commit before it builds.
- **Complete games:** the 1,000 games of the measurement above, at
  10+0.1 in `cutechess-cli` 1.5.1 on 2026-11-22, with the `avx2` build of
  the release's source. None ended by an illegal move, a crash, a stall or
  a loss on time. A soak test of the same search at 1+0, 3+2 and 60+0
  seconds (324 games) found no illegal move, crash or stall, and the one
  loss on time recorded as KI-12.
- **The release workflow** runs the gates again and smoke-tests every
  binary (`uci`, `isready`, `go depth 6`, `quit`) before it makes the
  release.
- **Not checked:** a chess GUI with this release, and lichess-bot with
  this release (the bot ran 0.1.0-alpha.2 when it was made).

## Getting it

Prebuilt binaries for x86-64 are attached to the GitHub release `v0.1.0`,
each with a `.sha256` file in the usual `sha256sum` format to check the
download against (`sha256sum -c <file>.sha256`):

| File | System | Build |
| --- | --- | --- |
| `vyvrael-0.1.0-avx2.exe` | Windows | `avx2`, the primary build |
| `vyvrael-0.1.0-avx2` | Linux | `avx2`, the primary build |
| `vyvrael-0.1.0.exe` | Windows | plain, for older machines |
| `vyvrael-0.1.0` | Linux | plain, for older machines |

All four are built by the release workflow from the tagged commit, never
with `target-cpu=native` or AVX-512. Binaries are never committed to the
repository itself.

To build from source, with the Rust toolchain `rust-toolchain.toml` pins
(`rustup` installs it on first use):

```sh
cargo build --release    # binary at target/release/vyvrael
```

The engine has no dependencies. Licence: GPL-3.0-or-later; the brand assets
in `branding/` are all rights reserved and not under the GPL.
