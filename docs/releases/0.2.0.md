# Vyvræl 0.2.0

*A dragon-flavoured UCI chess engine in Rust, built with AI and playing for
the attack.*

The search heuristics release. The search gained a transposition table,
move ordering, null-move pruning, late move reductions and reverse
futility pruning, each accepted by a sequential test against the search
before it. Full-strength play changes for the first time since
0.1.0-alpha.1, and `Hash` now does something.

## Read this first

- **Which file to take:** `vyvrael-0.2.0-avx2.exe` (Windows) or
  `vyvrael-0.2.0-avx2` (Linux), the primary build, for any processor with
  AVX2 and BMI2 (Intel from Haswell, 2013; AMD from Excavator and Zen).
  New in this release: `vyvrael-0.2.0-pext.exe` and `vyvrael-0.2.0-pext`,
  the same level with sliding-piece attacks by the PEXT instruction, for
  processors where PEXT is fast (Intel from Haswell, AMD from Zen 3). It
  plays the same moves; do not take it on AMD before Zen 3, where PEXT is
  slow. Take the plain `vyvrael-0.2.0.exe` or `vyvrael-0.2.0` only on an
  older machine where the `avx2` file does not start.
- **Breaking for GUI settings:** `UCI_Elo` now runs from **750 to 1380**
  (it was 1110 to 1630), with the default **1110** (it was 1360). The
  seven measured levels of weakened play are the same; their numbers are
  new, because they are now on the scale of a new opponent ladder. A
  number kept from 0.1.0 plays stronger than it did, and a value above
  1380 is refused, the old value staying. The table of old and new
  numbers is in
  [UCI.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/UCI.md),
  "Limited strength".
- **Measured, provisionally.** In a round robin of 44 engines on the
  project's own opponent ladder, the build of 0.2.0 finished 19th with
  92.5 points of 172, level with Tantabus 1.0.2 and Stockfish 19 limited
  to 2400 and 2200, and it won all twelve games against 0.1.0 and its two
  alphas, which finished 34th to 36th. Ordo puts it at -1418.8 with
  Stockfish 19 as 0. **This is an ordering against other engines on a
  stretched scale, not a Lichess, CCRL or FIDE rating,** it rests on four
  games against each opponent, and its error against the anchor is about
  ±200. Details below and in
  [results-0.2.0.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/testing/results-0.2.0.md).
- **The calibration and rating of 0.1.0 were provisional,** as its notes
  said. They are replaced by the ones here, which are provisional in
  turn: they hold for this build.
- **A casual-only Lichess bot** runs on the account `Vyvrael-Chess`, run
  by the maintainer. See
  [LICHESS.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/LICHESS.md).
- **Built under the 0rwx X scale.** The code is written by AI coding agents
  and curated by the maintainer, who does not read every line. Trust rests
  on the tests, the documentation and a history of small commits. See
  <https://0rwx.com/> and the
  [README](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/README.md).

## What is measured, and what is not

- **The rating cited here is of this release's search.** It was measured
  before the release, on the maintainer's Windows workstation, with an
  `avx2` build (`-C target-cpu=x86-64-v3`) built by hand with the local
  toolchain: the same Rust version as the workflow, but its GNU target
  where the workflow builds for Windows with MSVC. It is the same build
  level as the released `avx2` file, not the workflow's binary itself.
  It was built from the release branch before the `UCI_Elo` numbers were
  refitted; the release's source differs from it in those numbers only.
  Full-strength play is the same, which the bench node count shows
  (28,175 for both); only its speed may differ slightly.
- **How:** Ladder Baseline 3, a round robin of 44 engines at 10 seconds
  plus 0.1 a move, 3,784 games, rated by Ordo: 40 other engines and four
  Vyvræl builds (0.1.0-alpha.1, 0.1.0-alpha.2, 0.1.0 and this one). The
  setup and the full table are in
  [ladder-Baseline-3.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/testing/ladder-Baseline-3.md),
  the scores of 0.2.0 against each opponent in
  [results-0.2.0.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/testing/results-0.2.0.md).
- **Against 0.1.0:** in the same run 0.1.0 scored 41.5 points of 172 and
  0.2.0 scored 92.5, and 0.2.0 won their four games. At the same time a
  move it searched to a median depth of 12, where 0.1.0 reached 4. On
  this ladder's scale the two are about 555 points apart; that is a
  distance on a stretched scale with an error of about ±200 on each
  number, and says "clearly ahead", not an Elo gain to quote.
- **How precise:** 172 games, four against each opponent. Neighbours in
  the table are not separated: 0.2.0, Tantabus 1.0.2, Stockfish 19-2400,
  Stockfish 19-2200 and MinimalChess 0.5 lie within 5.5 game points.
- **Not on the scale of 0.1.0's notes.** Those cited a rating on Ladder
  Baseline 2 (-1721.4 for 0.1.0). On Ladder Baseline 3 the same 0.1.0 is
  at -1973.7. Compare builds within one ladder only.
- **Each search change was tested by itself.** Every heuristic was
  accepted by a sequential probability ratio test (SPRT) of the engine
  with it against the engine without it; the runs are listed in
  [sprt-history.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/testing/sprt-history.md).
- **`UCI_Elo` is calibrated again, provisionally.** The seven levels of
  weakened play were measured again on the same ladder (2,200 games:
  1,960 against seven of its low rungs and 240 between neighbouring
  levels) and each given the number it was measured at: two plies
  of lookahead from 750, three from 1100, with less misjudgement as the
  number rises. A setting of 1,000 means about as strong as an engine
  rated 1,000 on this ladder's scale (Ordo's number plus 3,500, so
  Stockfish 19 is 3,500 and full-strength 0.2.0 about 2,080), not a
  1,000 player. From 1021 to 1099 the
  engine plays as 1020. See
  [TESTING.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/TESTING.md),
  "Calibration of `UCI_Elo` (0.2.0)".
- **Both are provisional:** they hold for this build, and are measured
  again after the planned speed work.
- **Not measured:** the `pext` build in play (it gives the same moves and
  node counts; perft was about 4% faster with it on the maintainer's
  workstation), strength in a chess GUI against people, and anything
  about Lichess ratings.

## What is new

- **A transposition table.** The search remembers what it found for each
  position and uses it when the position comes up again. `Hash` sets its
  size, `ucinewgame` empties it, and the new button `Clear Hash` empties
  it without starting a new game. `info` lines report `hashfull`.
- **Move ordering:** the table's move first, then captures by what they
  win (with a static exchange evaluation, so that losing captures come
  last), then killer moves.
- **Pruning and reductions:** null-move pruning with a verification
  search where zugzwang is likely, late move reductions, and reverse
  futility pruning.
- **`go mate N`** searches for a mate in N moves or fewer, and
  **`go searchmoves`** restricts the search to the moves given.
- **Also in the protocol:** `seldepth` in the `info` lines, the option
  `UCI_ShowWDL`, and the commands `d` and `eval` in UCI mode.
- **The `pext` build** (see "Read this first"), from the Cargo feature
  `pext`.
- **Fixed:** `stop` and the clock now reach a long first search depth,
  and a clock within `Move Overhead` is no longer spent a millisecond at
  a time.
- **For developers:** search statistics (`search --stats` and the option
  `SearchStats`), a runner for EPD test suites (`suite`), and a round
  robin mode in the match scripts, which played Ladder Baseline 3.

The full list is in the
[changelog](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/CHANGELOG.md).

## Known limitations

From the "Known issues" table in
[ROADMAP.md](https://github.com/NexxusDrakoMultimedia/Vyvrael-Chess/blob/v0.2.0/docs/ROADMAP.md):

- **KI-10:** the first root move of the first search depth cannot be
  interrupted, and neither can the first pass of the weakened search, so
  a position with very many captures can overrun a very short time
  budget.
- **KI-12:** a long game with no increment and a tiny clock can still be
  lost on time. Games with an increment are not affected.
- **KI-8:** the evaluation is untuned; strength is measured for the
  builds named in the results files only.
- **KI-2:** FEN parsing is strict and has no repair mode for sloppy input.
- **KI-11, KI-13:** two limitations of the developer tools (the
  lichess-bot installer and the rating script).

Also: `Threads` can only be 1, there is no pondering, and several
well-known search techniques (history heuristics, principal variation
search, aspiration windows, check extensions) are not in yet.

## How it was checked

- **Tests:** 567 Rust tests (unit tests and the integration suites:
  perft, UCI over real pipes, malformed input, pinned search results and
  the pinned bench count, whole games) and 335 tests of the helper
  scripts, all passing, with `cargo fmt` and `cargo clippy -D warnings`
  clean, on the maintainer's Windows workstation. The release workflow
  runs the same gates again on the tagged commit before it builds, and
  runs the engine's tests on the `pext` build too.
- **Complete games:** the 172 games of 0.2.0 in Ladder Baseline 3 and the
  2,200 games of the `UCI_Elo` calibration, at 10+0.1 in `cutechess-cli`
  1.5.1 on 2026-11-28, with the hand build described above. None ended
  by an illegal move, a crash, a stall or a loss on time.
- **The release workflow** smoke-tests every binary (`uci`, `isready`,
  `go depth 6`, `quit`) before it makes the release.
- **Not checked:** complete games with a build of the final release
  commit (the build that played predates the refit of the `UCI_Elo`
  numbers, which changes no move at a given level), the workflow's `pext`
  job before this release, a chess GUI with this release, and lichess-bot
  with this release.

## Getting it

Prebuilt binaries for x86-64 are attached to the GitHub release `v0.2.0`,
each with a `.sha256` file in the usual `sha256sum` format to check the
download against (`sha256sum -c <file>.sha256`):

| File | System | Build |
| --- | --- | --- |
| `vyvrael-0.2.0-avx2.exe` | Windows | `avx2`, the primary build |
| `vyvrael-0.2.0-avx2` | Linux | `avx2`, the primary build |
| `vyvrael-0.2.0-pext.exe` | Windows | `pext`, where PEXT is fast |
| `vyvrael-0.2.0-pext` | Linux | `pext`, where PEXT is fast |
| `vyvrael-0.2.0.exe` | Windows | plain, for older machines |
| `vyvrael-0.2.0` | Linux | plain, for older machines |

All six are built by the release workflow from the tagged commit, never
with `target-cpu=native` or AVX-512. Binaries are never committed to the
repository itself.

To build from source, with the Rust toolchain `rust-toolchain.toml` pins
(`rustup` installs it on first use):

```sh
cargo build --release    # binary at target/release/vyvrael
```
