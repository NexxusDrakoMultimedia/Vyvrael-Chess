# Vyvræl 0.1.0-alpha.2

*A dragon-flavoured UCI chess engine in Rust, built with AI and playing for
the attack.*

The second alpha. It plays exactly as 0.1.0-alpha.1 did at full strength,
and adds what the first one lacked for a bot and for measuring: games that
need not repeat, a seed that a GUI can store, and a reproducible bench.

## Read this first

- **Which file to take:** this release ships plain builds only, for any
  x86-64 processor: `vyvrael-0.1.0-alpha.2.exe` for Windows and
  `vyvrael-0.1.0-alpha.2` for Linux. The `avx2` and `pext` builds start
  with 0.1.0, the first release built by a workflow.
- **Breaking for settings and scripts:** the options `DeterministicRNG` and
  `RngSeed` are gone. **`Seed`** replaces them: 0 (the default) takes a new
  seed from system entropy for every game, any other number up to
  2147483647 fixes it. A GUI or script that still sets the old options gets
  "unknown option" for them.
- **Strength is still unmeasured** (known issue KI-8) and **`UCI_Elo` is
  still not calibrated**: its settings are ordered, not measured. The only
  measurement so far is a snapshot of 0.1.0-alpha.1 against the lower rungs
  of Ladder Baseline 1
  ([results-0.1.0-alpha.1.md](../testing/results-0.1.0-alpha.1.md)). It
  applies to this release too, because full-strength play is unchanged: the
  bench node count is the same with the new options at their defaults. It
  is an ordering on a stretched scale, not a rating. Measuring against the
  new reference ladder, Ladder Baseline 2, is milestone 6.
- **A casual-only Lichess bot** runs on the account `Vyvrael-Chess`, run by
  the maintainer. Rated games wait until after 0.2.0. See
  [LICHESS.md](../LICHESS.md), which now suggests `Variety: 10` for the bot.
- **Built under the 0rwx X scale.** The code is written by AI coding agents
  and curated by the maintainer, who does not read every line. Trust rests
  on the tests, the documentation and a history of small commits. See
  <https://0rwx.com/> and the README.

## What is new

- **`Variety`** (0 to 100 centipawns, default 0). In the first 12 full
  moves, at full strength, the engine plays at random among its best move
  and the moves a second search checks to be within `Variety` of it,
  weighted towards the best, so that its games do not repeat. Never when
  the best score is a mate; a move that could not be checked in time is
  never played; an `info string` says when a move other than the best was
  played. With 0 play is exactly as before. It weakens play on purpose:
  keep it at 0 in any match that measures strength.
- **`Seed`** (0 to 2147483647, default 0), in place of `DeterministicRNG`
  and `RngSeed`. The seed in use is logged with `info string` in reply to
  `uci` and at every `ucinewgame`, so any game can be replayed by giving its
  logged seed back. The range fits Cute Chess, which reset `RngSeed` to 0
  whenever it was edited.
- **Deterministic play** is one thread, a fixed `Seed`, `Variety` 0 and a
  fixed depth or node count.
- **`vyvrael bench`**: seven fixed positions searched to depth 4 at full
  strength, printing `<nodes> nodes <nps> nps`. The node count (16,611,416)
  is the same on every run and every machine; it changes only when what the
  search does changes.
- **Testing tools** (for developers, not needed to play): match and rating
  scripts for Windows and Linux around `cutechess-cli` and Ordo, and an
  installer for both tools and for the opponent engines of Ladder Baseline
  2, on Linux and Windows, in an `avx2` or `pext` build. See
  [TESTING.md](../TESTING.md).

The full list is in the [changelog](../../CHANGELOG.md).

## Known limitations

From the "Known issues" table in [ROADMAP.md](../ROADMAP.md):

- **KI-8:** the evaluation's strength is unmeasured.
- **KI-9:** the search is slow without move ordering; it plays shallowly for
  the time it uses.
- **KI-10:** the first search depth cannot be interrupted, and in positions
  with very many captures it can overrun a short time budget.
- **KI-2:** FEN parsing is strict and has no repair mode for sloppy input.
- **KI-11:** the installer does not repair a half-made virtual environment
  for lichess-bot.

Also: `Hash` is accepted but has no effect yet, `Threads` can only be 1, and
there is no pondering, `searchmoves` or `go mate`.

## How it was checked

- **Tests:** 457 Rust tests (439 unit tests and the integration suites:
  perft, UCI over real pipes, pinned search results and the pinned bench
  count, a consistency walk of the move tree, whole games) and 232 tests of
  the helper scripts, all passing, with `cargo fmt` and `cargo clippy -D
  warnings` clean. They passed on the maintainer's Windows workstation and,
  for the release commit, on the maintainer's Linux machine.
- **The bench** gave 16,611,416 nodes on both machines, the same count as
  before `Seed` and `Variety` were added.
- **Complete games** in `cutechess-cli` 1.5.1 at 10+0.1 on the Windows
  workstation, with the Windows binary above, on 2026-11-22: 48 games
  against the six core opponents of Ladder Baseline 2 (eight each), and 20
  games of self-play with `Variety` 10 on both sides, as the bot will play.
  None ended by an illegal move, a crash, a stall or a loss on time. In the
  self-play none of the ten opening pairs was repeated move for move (in
  the self-play of 0.1.0-alpha.1, three of ten were). This checks that
  games complete and vary; it measures nothing about strength. Details are
  in [TESTING.md](../TESTING.md).
- **Not checked:** a chess GUI, and lichess-bot with this release (the bot
  ran 0.1.0-alpha.1).

## Getting it

Prebuilt binaries for x86-64 are attached to the GitHub release
`v0.1.0-alpha.2`, each with a `.sha256` file in the usual `sha256sum`
format to check the download against:

| File | System | Built on | SHA-256 |
| --- | --- | --- | --- |
| `vyvrael-0.1.0-alpha.2.exe` | Windows | the maintainer's Windows workstation | `1b0d518f26fcbb876f747449422c9d32ea249db0223f3ddec319ac4297c81ad3` |
| `vyvrael-0.1.0-alpha.2` | Linux | the maintainer's Linux machine | `64d91a6a24fd011b3e959a18d6ff295775def329f7568279a54342171d0d1fdd` |

Both are plain release builds of commit `105d8d5` for any x86-64 processor,
made by hand without any processor-specific setting. This is the last
release built by hand: from 0.1.0 the binaries come from a workflow, in
`avx2`, `pext` and plain builds. Binaries are never committed to the
repository itself.

To build from source, with a stable Rust toolchain:

```sh
cargo build --release    # binary at target/release/vyvrael
```
